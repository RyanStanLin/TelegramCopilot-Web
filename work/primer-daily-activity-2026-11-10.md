## Implementation plan

- `/presence?target=...&date=YYYY-MM-DD&timeZone=...`: person/day detail, following the detail template and user-provided Screen Time task hierarchy. PageHeader identifies the person; local date and timezone are primary controls. Native Primer Pagination provides chronological previous/next dates. Daily duration/count/longest observed span/known coverage form one compact definition group, not a decorative card array.
- Primary 00:00–24:00 chronological chart positions each interval at its real time. Semantic gray=known Offline, green=Online, red=observation interruption (the user's explicit clarification). Neutral outlined unknown and future time remain separate, with text alternatives. No state percentage is used as a timeline coordinate.
- Hourly distribution and seven-day trend support actual quantities and selecting a day/metric. Axes and units are visible; equivalent tables and CSV remain available. The official ProgressBar represents completion/parts of a whole, not absolute time positions, so it is not misused. Primer has no quantitative timeline/hourly chart; minimal SVG data marks are a documented extension, not icons. SVG coordinates express time/count data; semantic styles and canvas sizes use verified tokens. A focused chart cursor has keyboard and text readout equivalents.
- Actual Primer Timeline lays out chronological human-readable sessions and monitoring gaps, with compact time/duration and secondary technical details. Pagination is official Primer, not custom. Historical range queries, contribution calendar and raw metadata remain in progressive disclosure, preserving existing URLs and export.
- Mobile keeps the existing sticky shell/Dialog navigation. Stack responsive directions produce one column; charts fit their containers. Controls wrap and all digits use NumericText/monospace. No new decorative motion, comments, gradients, shadows, arbitrary font/color or private component selectors.
